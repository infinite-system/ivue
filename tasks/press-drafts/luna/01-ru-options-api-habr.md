# Анатомия вернулась: компонент снова можно прочитать

Вы открываете незнакомый Vue-компонент и сразу видите, где его состояние, вычисления и действия. Для этого больше не нужен DSL Options API: ivue возвращает эту структуру обычному TypeScript-классу.

ivue — слой классов размером 1,1 kB поверх реактивности Vue. Состояние остаётся реактивным, экземпляр остаётся обычным объектом, а поведение можно наследовать и тестировать вне компонента.

## Что на самом деле нравилось людям в Options API

Людям нравились не сами секции `data`, `computed` и `methods`. Нравилась анатомия. Открыв чужой файл, можно было сначала понять его форму, а уже потом читать логику: здесь состояние, здесь производные значения, здесь действия.

Проблема в том, что эта анатомия была ненастоящей. Обычный объектный DSL выдавал себя за класс. `this` был runtime-прокси, с которым TypeScript годами спорил. Одна логическая задача раскладывалась по трём секциям. Повторное использование означало mixin, поверхностное слияние опций и коллизии имён. Свойства могли появиться в `this` из файла, которого читатель никогда не открывал.

И всё это существовало только внутри компонента. У этой «классовой» формы не было экземпляра, который можно сохранить, протестировать или передать другой части программы.

Composition API исправил повторное использование и типизацию, отказавшись от анатомии. `setup()` честен: это обычные функции и реальные замыкания. Но у `setup()` нет формы. Поэтому каждая команда заново придумывает порядок секций и получает свой вариант setup-soup.

Наблюдение ivue простое: нужная анатомия всё это время была в самом языке. Класс — это Options API без притворства. Каждая секция возвращается как вид члена класса, а обещания становятся механизмами.

```js [Options API]
export default {
  data() {
    return { count: 0 };
  },
  computed: {
    double() {
      return this.count * 2; // `this` is a proxy; typing it took years
    },
  },
  methods: {
    increment() {
      this.count++;
    },
  },
};
```

```ts [ivue]
// counter.ts
import { Reactive } from 'ivue';
import { ref } from 'vue';

class $Counter {
  // data → a getter returning ref(); read and write via .value
  get count() {
    return ref(0);
  }

  // computed → a PLAIN getter: reactive via leaf tracking, zero
  // bytes per instance — no computed() unless the work is expensive
  get double() {
    return this.count.value * 2;
  }

  // methods → methods; the engine binds them lazily on the prototype
  increment() {
    this.count.value++;
  }
}

export namespace Counter {
  export const $Class = $Counter; // raw — children `extends` this
  export const Class = Reactive($Class); // reactive — you `new` this
  export type Instance = typeof Class.Instance; // defineExpose type & reactive() interop
}
```

## Та же анатомия, другой носитель

В ivue `this` остаётся `this`. Это обычный TypeScript без proxy-типов и без `ThisType`. Методы лениво связываются один раз с правильным экземпляром. Метод можно передать как обработчик, и его ссылка остаётся стабильной.

Производные значения участвуют в наследовании. Производное значение — это getter. Getter понимает `extends` и `super`, поэтому класс-наследник может заменить одно вычисление и сохранить остальную модель. У Options API были mixin, но не было такого наследования членов.

Секции не требуют отдельного узла на каждый экземпляр. Plain getter живёт на prototype и получает реактивность через чтение листовых значений. Поэтому вычисление, которое не требует кеша, не создаёт `computed()`.

В репозитории ivue панель администратора содержит одиннадцать моделей и store, связанный с роутером. В них используется **ноль вызовов `computed()`**. Это не правило «никогда не кешировать». Кеш выбирается только когда дорогая работа, равенство значения или стабильная ref-ссылка оправдывают примерно 300 байт на экземпляр.

Экземпляр существует и за пределами компонента. Те же соглашения работают в newsletter Worker на ivue.dev: планировщик, доставка и OAuth-подписант не требуют SFC. Options API была привязана к компоненту. Класс можно создать, сохранить, протестировать и передать куда угодно.

## Честная граница

ivue не заменяет Composition API. Он построен поверх него. `ref()`, `watch()`, lifecycle hooks и composables работают внутри конструктора, который синхронно выполняется в контексте `setup()`.

Composition API даёт механизм. Класс возвращает структуру, в которой этот механизм можно читать.

Это не третья независимая парадигма. Options API обещала анатомию, но строила её на прокси-объекте. Composition API дала честную механику, но убрала форму. Класс сохраняет обе части: состояние, производные значения и действия снова находятся рядом, а повторное использование выражается наследованием и обычными объектами.

## Что измерять

Размер и скорость здесь не лозунги. Они проверяются в браузере и в репозитории:

- engine ivue — **1,1 kB gzip**, ноль зависимостей и 100% test coverage;
- создание экземпляров выполняется в **55–253 раза быстрее** альтернативных форм в опубликованном сравнении;
- слой может представить **20 000 000 ячеек** по 4,7 байта на ячейку;
- производные getter-ы не получают `computed()` автоматически и не платят за кеш, пока кеш не нужен.

Метод измерения важнее отдельного числа. Для каждого результата нужно указать размер модели, версию Vue, среду выполнения и то, удерживались ли экземпляры. Именно это делает сравнение проверяемым.

## Начало

```sh
npm i ivue vue
```

Документация: https://ivue.dev/guide/getting-started

Откройте форму класса, затем проверьте реактивность и тесты на своей модели. В этом и состоит выигрыш: вы читаете обычный TypeScript, а сигнализируется только то, что реально было прочитано.
