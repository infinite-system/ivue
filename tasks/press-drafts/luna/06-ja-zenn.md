# クラスのまま、Vueのリアクティブ状態を持てる

Vueで状態を管理するとき、コンポーネントの中にロジックを閉じ込めず、通常のTypeScriptのクラスとしてモデルを持ちたいことがあります。一方で、クラスごとにproxyや大量のcomputedを用意すると、インスタンス数に比例したコストが増えます。

ivueは、Vue 3のリアクティビティの上に置く1.1 kBのクラス層です。通常のTypeScriptクラスをリアクティブなモデルとして扱えます。インスタンスはproxyで包まれず、コンポーネントの外でも生成できます。

最小の例です。

```ts
import { Reactive } from 'ivue'
import { ref } from 'vue'

class $Counter {
  get count() {
    return ref(0)
  }
  get double() {
    return this.count.value * 2 // plain getter — derives on read
  }
  increment() {
    this.count.value++
  }
}

export const Counter = Reactive($Counter)
```

`Reactive()`はprototypeを一度だけ変換します。`ref()`を返すgetterは状態として扱われ、最初にアクセスした時点でセルが作られ、以後は同じセルが使われます。値を返すだけのgetterは、通常のgetterのままです。そのgetterがeffectの中でリアクティブな値を読むと、Vueはその読み取りを追跡します。派生値ごとに`computed()`を作る必要はありません。

メソッドは必要になった時に正しい`this`へ束縛されます。イベントハンドラとして取り出しても、毎回クロージャを作る必要がありません。状態の読み書きは、クラス内部では通常のVueのルールに従い、`ref`の値を`.value`で扱います。クラスを読む人は、状態、派生値、操作を同じファイルで確認できます。

## 数字が示すもの

ivueのサイズは**1.1 kB gzip**です。依存関係は0、テストカバレッジは100%です。インスタンス生成のベンチマークでは、対照となる実装に対して**55–253倍**の差が測定されています。さらに、keyごとに必要な時だけリアクティブなversion signalを作る設計により、**20,000,000セル**のモデルを4.7 bytes/セルで表現できます。

これらは、短いコードを書いたという話ではありません。何を先に作るかを決める話です。状態は存在していても、まだ観察されていないセルを先に割り当てる必要はありません。派生値は、すでにある信号を読むだけなら、別のキャッシュノードを持つ必要はありません。モデルがコンポーネントより長く生きるなら、その寿命をコンポーネントに預ける必要はありません。

この判断は、機能名ではなく不変な条件から始めます。まず、削除しても動作が変わらない機構を消します。次に、残った構造からすべての有効なケースを生成できるか確認します。最後に、何が起きないはずかを確認します。たとえば、観察されていないkeyへの書き込みは、信号を割り当てず、購読者も通知しません。これは「最適化したい」という希望ではなく、読み取りと書き込みの役割が異なるという設計上の境界です。

## Composition APIとの関係

ivueはComposition APIの代替ではありません。`ref()`、`watch()`、ライフサイクルフック、composableはそのまま使えます。クラスのconstructorは`setup()`の中で同期的に実行されるため、コンポーネントに結びついたwatchやライフサイクルも、通常のComposition APIのスコープに登録できます。

同じクラスの規約は、Vueコンポーネントの外でも使えます。ivue.devのnewsletter Workerや、AI agentsが構築したInvarのモデル層がその例です。Invarは現在、約**94,000行**のIDEソースを持ち、コードベース全体で`computed()`は1つです。必要なキャッシュだけを選び、それ以外は読み取りから派生させています。

## 試してみる

```sh
npm i ivue vue
```

まずは小さなモデルを作り、生成時間、メモリ、読み取り回数を測ってください。数字には、モデルのサイズ、Vueのバージョン、実行環境、インスタンスを保持したかどうかを添えます。測定方法がなければ、数字は比較になりません。

ドキュメントとブラウザ上のベンチマークは https://ivue.dev で確認できます。
