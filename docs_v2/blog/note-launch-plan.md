# Launch plan & channel notes

**Post order:** HN first (weekday, 8–10am ET — traffic feeds
everything else), r/vuejs same day, LinkedIn next morning (its algo
rewards fresh, not simultaneous), r/javascript + lobste.rs day 2,
dev.to cross-post (canonical link to ivue.dev) whenever. X thread the
moment credits exist — the composer already has the thread built.

**Links used throughout:**

- https://ivue.dev/blog/introducing-ivue (THE entry point — always first)
- https://ivue.dev/blog/the-options-api-everyone-wanted
- https://ivue.dev/blog/bulletproof-class-modules
- https://ivue.dev/blog/discovered-not-invented
- solved-problem receipts: /blog/circular-imports-dissolved,
  /blog/this-method-era, /blog/initialization-order-solved
- https://ivue.dev (home) · https://ivue.dev/guide/standard (the manual)

## Also worth submitting

- **lobste.rs** — submit the Bulletproof class modules post directly
  (tag: javascript, practices). Lobsters prefers the article over the
  pitch.
- **dev.to** — cross-post "The Options API everyone actually wanted"
  in full with canonical_url set to ivue.dev; large Vue audience,
  zero self-promo penalty.
- **Vue newsletters** — submit to Weekly Vue News, Michael Thiessen's
  newsletter, and vuejsdevelopers.com; they take submissions and the
  Options API angle is exactly their readers' fight.
- **Echo JS / daily.dev** — link drops, no extra copy needed.
- **r/typescript** — the two-inheritance-chains + `self` material
  lands well there; reuse the r/javascript angle.

## Notes on tone per room

- **HN:** the first comment deliberately names two weaknesses (v-for
  `.value`, 4ns bound calls). HN trusts posts that ship their own
  criticism; never delete that paragraph.
- **Reddit:** answer every technical comment with numbers or a repo
  link; never adjectives.
- **LinkedIn:** it's the only room where "profound" energy works —
  but it stays in the structure (the arrows, the discovery arc),
  never in adjectives.
- **Everywhere:** the newsletter invite is one line, benefit-framed,
  last.

## Podcasts & outreach

The pitch is never "my library" — it's one of two STORIES, picked per
room:

- **The Vue story** — "the Options API everyone actually wanted:
  classes weren't broken, they were unconstrained." For Vue-native
  rooms; controversy is the hook, receipts are the armor.
- **The agent story** — "AI agents built a 94,000-line terminal IDE
  by following a one-document standard — here's what makes a codebase
  agent-legible." Works in ANY dev room, and it's the rising tide.

Targets, in rough order of fit:

- **DejaVue** (Alexander Lichter & Michael Thiessen) — THE Vue
  podcast; Michael's newsletter is already on the submissions list,
  so one relationship covers two channels. Vue story.
- **Views on Vue** (Top End Devs) — interview format, welcomes
  library authors. Vue story.
- **PodRocket** (LogRocket) — frontend-general, likes measured-perf
  angles. Either story.
- **devtools.fm** — tools-for-developers focus; the Invar + standard
  angle fits exactly. Agent story.
- **JS Party / Syntax** — long shots but the agent story is their
  kind of episode; pitch after HN traction, link the thread.
- **Conference CFPs** (Vuejs Amsterdam, Vue.js Nation, Nuxt Nation) —
  the agent story as a talk: "constraints make codebases
  agent-writable." CFP deadlines run months ahead — submit early,
  they compound the podcast credibility.

Outreach mechanics: short pitch (three sentences, one link, one
number), sent AFTER the HN/Reddit wave so there's a thread to point
at. Podcasters book on proof of audience interest — the launch IS the
pitch material.
